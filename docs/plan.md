# slack-notice: implementation plan

Implements [interface.md](interface.md) and [design.md](design.md). The issues for each stage are expanded into bite-sized test-first steps when they are picked up; this plan fixes the order, the conventions and the module map.

## Conventions for every stage

- **Gateway boundary.** All HTTP (`http.client`), TLS context, clock and lock-file access goes through `src/slack_notice/gateway.py`; modules never import `urllib`, `http`, `time`, `fcntl` or `subprocess` directly. Tests substitute a fake gateway.
- **Fake gateway.** Process tests call `cli.main(argv, env, gateway)` with a fake gateway in-process, because the URL must be on `hooks.slack.com` and verification cannot be disabled; no test-only environment seam is allowed. The fake gateway supplies name resolution, the monotonic clock, the home directory and uid, input reading, state-directory access hooks where a test needs a hostile path, the CA path candidates, and a response script (each row of the interface's Webhook edge table, including a 200 with a wrong body, a 3xx and a 5xx), a delay, a stalled name resolution, a stall after the first byte, a trickled response, a TLS failure and a post-write failure. There are no tests on a network socket: the wire-format and TLS tests run the real connection class over an in-process socketpair (the TLS ones need the `openssl` CLI to make a certificate) and never open or resolve a real address. There are no sibling tools to pin.
- **Process and live split.** Only the `live` tests (pytest marker, never in CI) touch the network: they post to the maintainer's own workflow and are listed in the live-verification issue. The suite is written (`tests/test_live.py`, `make live`, [live-testing.md](live-testing.md)); its acceptance is the maintainer's own run.
- **Golden files.** `--json` outputs, rendered bodies and log records have golden files; a golden hash test (fixed input, expected `message_sha256`) and a golden serialization test (`ensure_ascii=False`, compact separators, key order); schemas have positive and negative samples.
- **Spike regressions.** Every behavior in design.md's live-verification table becomes a fake-gateway test or a `live` test.
- **Secrets.** A test sets a recognizable fake URL and asserts it appears in no argv, output, log, error or file; a test injects `InvalidURL` and `ValueError` carrying the fake URL and asserts it is absent from stdout, stderr and the log.
- **Environment.** A test with a fake proxy variable and a fake `SSL_CERT_FILE` asserts zero connections reach the proxy and the fake CA is not trusted; a redirect test asserts a second server receives zero requests.
- **`make verify`** passes before every commit; each paragraph in markdown is one line.

## Module map

| Module | Stage | Responsibility |
|---|---|---|
| `gateway.py` | 0 | HTTP, TLS context, clock, name resolution, home directory, `is_directory` and uid, input reading, CA path candidates, state files; also `wall_time`, `sleep`, `login_name`, `read_regular_file`, `try_lock`, `unlock`, `file_size`, `file_mtime`, `set_mtime`, `read_at`, `write_fd`, `truncate_fd`, `rename_state_file` and the `StateUnusable` and `NotRegularFile` errors. |
| `cli.py` | 0, 3, 4 | Parsing, dispatch, exit codes, output. |
| `config.py` | 1 | Config, drop-ins, YAML, durations. |
| `log.py` | 1 | State directory, log records and rotation. |
| `payload.py` | 2 | Input reading, validation, sanitizer, link rule. |
| `render.py` | 2 | Body layout and cuts. |
| `spacing.py` | 3 | Send lock and 1 s spacing. |
| `webhook.py` | 3 | URL allowlist, one attempt (`post_once`, `AttemptResult`, `Phase`, `Failure`; #23), response mapping. |
| `deadline.py` | 3 | The deadline (#25): `Deadline` (three-state gate and result slot under one lock, daemon worker, wait in slices), `attempt_work` (the retry loop, #26), `conclude` (print and flush in a daemon thread bounded to 1 s, then the log step, then `gateway.exit_now`). |

## Stage 0: Scaffold and gateway

**Goal**: A package that installs, prints `--version`, and has the gateway and the fake gateway in place.
**Success Criteria**: `make verify` green; schemas load; the fake gateway serves each response row.
**Tests**: version output golden; fake gateway contract tests; schema positive and negative samples.
**Status**: In Progress

`webhook_env` that looks like a URL says "must be a variable name"; `HOME` and `XDG_CONFIG_HOME` set to a directory with a hostile config (not read), `HOME` unset (the fake gateway's home directory is used), a home lookup that fails, returns an empty or relative path or a directory that does not exist (exit 2 `config_invalid`, `details.key` `home`, nothing read or sent; a `send --dry-run --config` still works; the actor name falls back to `unknown` when the entry has no name), `--config` plus drop-ins in its directory; a strict-loader table (`enabled: no`, `off`, `yes`, `timeout: 010`, `timeout: 1:30`, `0x10`, `1_0`, `.inf`, `.nan` all `config_invalid`; `enabled: true`, `timeout: 10`, `timeout: 1.5` accepted); a duplicate key in a config file and in a drop-in (`config_invalid`); a cyclic anchor (`a: &a [*a]`) and any parser error during load, merge or validation (`config_invalid`, no snippet echoed); ## Stage 3: Webhook send, spacing and the deadline

**Goal**: A real `send` against the fake gateway with the full response table.
**Success Criteria**: every row of the Webhook edge table maps to its exit code and envelope; spacing queues concurrent callers; the URL is checked and never leaked; the result is printed within 1 s of the deadline and the process ends within `timeout` plus 3 s; the result is printed before the log step.
**Tests**: response table; 429 three times (waits 2 s and 4 s; the gate returns to idle after each 429, and a deadline during the 2 s wait, the new name resolution, the connect or the handshake of a retry reports `rate_limited` with retryable true, never `outcome_unknown`; no write follows an `abandoned` gate; a retry that is writing when the deadline passes is `outcome_unknown`), connect-refused retried once, 5xx not retried, a `Retry-After` header of any value (`nan`, `-5`, `1e999`, an HTTP date, `5`, `45`, `0`, `²`) ignored with waits staying 2 s and 4 s, 429 twice then connection refused (independent counters, four requests at most); a table test per exception class in both phases (`ConnectionResetError`, `BrokenPipeError`, `TimeoutError`, `ssl.SSLEOFError`, `RemoteDisconnected`, `BadStatusLine`, `LineTooLong`, `IncompleteRead`, `InvalidURL`: before the first byte `network_error`, after it `outcome_unknown` or `wrong_host_response` per the interface); an uncaught worker exception prints nothing and exits 1 with the class name; CA fallback (compiled cafile exists but is empty and the capath is missing: the fallback list; the capath is an existing directory with unrelated entries: used as given, the failure is `network_error` with `tls: true`, not retryable, no fallback; nothing usable at all: `tls: true` with "no usable CA certificates"); a fake gateway that blocks connect past the deadline and then proceeds (`network_error` reported, zero request bytes written, exit 12), one that blocks after the first byte (`outcome_unknown`), a signal during the lock wait, a trickled response (result printed within 1 s of the deadline, exit within `timeout` plus 3 s), a response that is complete at the exact deadline (200 `{"ok":true}` is `sent`; 400 and 429 are reported as such, never `outcome_unknown`; the main thread checks the result slot first), a fake log step that takes 5 s (the result is already on stdout and flushed, the log lock poll ends at 1 s), a worker `BaseException` after the gate moved to writing (exit 1, class name only, logged as `outcome_unknown`), a `daemon=True` assertion (process exit does not wait for a blocked worker); envelope tests per cell of the exit-12 table (including `unavailable` with `details.phase` `input` and `lock`), a deadline hit after the first byte follows the same rule, a message of 5000 ESC characters as a field name (`details.pointer "/?"`); a failure after the first byte is `outcome_unknown` with no retry; envelope flags per code (`retryable`, `unknown_outcome`, `retry_after_s`); deadline tests (stalled name resolution, stall after the first byte, response trickled byte by byte, SIGTERM); concurrent sends spaced by the lock's mtime, a first send with an empty state directory has no wait, two processes creating the file at once (the second sees size 1 and waits one second), a zero-size file left by a crashed first send (no wait, then marked), a future mtime ignored, the lock released before the log record (the fake records the order), a lock wait that outlasts the deadline exits 12 `unavailable` (`details.phase` `lock`); URL allowlist table (valid with 1 to 4 segments, ASCII-whitespace trim at the edges including VT and FF and no other character trimmed (NBSP, U+2028, U+FEFF, ZWSP, C0 separators refused), a value of exactly 1024 characters after trimming accepted and 1025 refused, a query, a port, userinfo, a trailing dot, an empty segment, another host, empty, unset): `credential_invalid` with `details.env`; a token containing CR LF; `enabled: false` exits 22 without draining stdin; exit-1 handler prints only a class name; golden hash and serialization tests.
**Status**: Not Started

## Stage 4: `validate`, live verification and docs

**Goal**: `validate [--test-message]`, the live suite and user documentation.
**Success Criteria**: validate checks match the interface; the live suite passes against the maintainer's workflow and settles the still-to-verify items V1 to V5, V18 and V21; the first live assertion is that the maintainer's own trigger URL matches the allowlist (V4), a release criterion: 0.1.0 is not tagged until it passes; README documents workflow setup and cron use.
**Tests**: validate golden files (no prompt in any case; `enabled` reported; a disabled tool with plain `validate` exits 0 with `enabled: false`; a disabled tool with a broken credential exits 12; `--test-message` on a disabled tool exits 22 with no call and before any check, even with an unset credential; `validate --dry-run --test-message` still sends); live tests (plain message, limit-sized message, non-ASCII byte versus character limit, the four default emoji arrive intact, auto-link, burst and sustained-rate spacing, 403/404/410 where reproducible, a `GET` on a trigger URL).
**Status**: Not Started

## Version roadmap

- **0.x**: Stages 0 to 4.
- **1.0** when the live suite has passed and the tool has run in daily use through a routing tool for two weeks without an interface change.
- **1.x, additive**: a configurable `min_interval` after the sustained-rate test; a `chat.postMessage` transport for users who can obtain an app token (formatting, mentions, self-DM); an optional headless-Claude transport; classic incoming webhook support; a read-only `GET` probe if V2 shows it works; `limits` in `validate --json`.
- **2.0**: nothing planned.
